PROPOSTA DE MELHORIA - SELEÇÃO DE IDIOMA E API DO GOOGLE
Status: IMPLEMENTADA, PENDENTE DE TESTE PONTA A PONTA (07/10/2026)
Validado apenas: compilação dos módulos e seleção de trilha com dados simulados. Tradução e multiplexação reais ainda não foram executadas.

1. O Problema
O Google Translate, quando deixado no "auto" (autodetectar), pode se confundir em frases curtas, gírias ou nomes próprios.
Além disso, o idioma de origem enviado à API era sempre o valor global do menu. Se o usuário escolhia "eng" e o vídeo só tinha uma faixa "jpn" (fallback), o Google recebia "en" para um texto japonês, gerando uma tradução quebrada. Em lotes com idiomas mistos, o menu voltava para "auto".

2. A Solução (implementada)
A camada de extração (MkvWrapper) agora devolve o idioma REAL da faixa extraída, mesmo quando há fallback. O orquestrador repassa esse idioma ao TranslatorService, que informa o código exato à API (src="ja"), evitando o autodetect sempre que o idioma for conhecido.

3. O que foi alterado

A) tradutor/idiomas.py (NOVO)
Classe Idiomas, com o mapeamento centralizado:
- para_google(codigo): converte ISO-639-2 do MKV (ex: "jpn") para o código do Google (ex: "ja"). Retorna "auto" para idiomas desconhecidos ("und", "mul", não mapeados).
- destino_para_mkv(codigo_google): devolve (código ISO-639-2, nome da trilha) para o mkvmerge.
- O mapa foi ampliado de 10 para ~35 códigos (ex: kor, deu/ger, zho/chi, ara, tha, pol, nld, tur...). Antes, qualquer código fora dos 10 originais caía em "auto" silenciosamente.

B) tradutor/mkv_wrapper.py
- _selecionar_trilha retorna (track_id, extensão, idioma). Trilhas sem tag de idioma retornam "und".
- extrair_legenda retorna (caminho, idioma_real) e registra no log um aviso quando o idioma preferido não existe no vídeo: "[AVISO] Idioma 'jpn' ausente neste vídeo; usando a faixa 'fra'."
- embutir_legenda recebe o caminho de saída e o idioma de destino. Não usa mais "_PTBR" nem "por" fixos.

C) tradutor/orchestrator.py
- Usa o idioma_real retornado pela extração (arquivos avulsos continuam usando a preferência do usuário).
- Registra no log o idioma de origem e o código Google, ou avisa quando será usada a autodetecção.
- Pula o arquivo quando origem e destino são o mesmo idioma (ex: faixa "por" com destino "pt"), removendo apenas o temporário extraído. Vale SOMENTE para MKV: o idioma vem da própria faixa. Para legendas avulsas, o idioma vem do menu (pode ter sobrado de uma varredura anterior), então apenas avisa no log e prossegue.
- Passa ao mkvmerge o mesmo caminho de saída usado na checagem de conflito.

D) tradutor/translator_service.py
- _map_lang agora delega para Idiomas.para_google (mantido como wrapper por compatibilidade).

4. Correção de bug incluída (fora da proposta original)
Antes, o orquestrador verificava conflito em "<nome>_PT.mkv", mas o mkvmerge gerava "<nome>_PTBR.mkv". O aviso de sobrescrita nunca disparava e o arquivo existente era sobrescrito sem confirmação. Para destinos diferentes de português, o MKV também saía com nome e metadados de português. Agora o nome e o idioma da trilha seguem o destino escolhido.
ATENÇÃO: o nome do MKV de saída mudou de "_PTBR.mkv" para "_PT.mkv" (código do destino em maiúsculas).

5. Limitações conhecidas
- Se a tag de idioma do MKV estiver errada (comum em fansubs), forçar o idioma de origem pode ser pior que o "auto". A proposta reduz o risco, mas não o elimina.
- Idiomas fora do mapa continuam usando o autodetect (com aviso no log). Basta incluí-los em Idiomas._MKV_PARA_GOOGLE.
- Legendas avulsas (.srt/.ass) não têm metadado de idioma: usam o valor do menu, que pode estar desatualizado (ex: sobrou de um MKV escaneado antes). Nesse caso o idioma de origem enviado ao Google pode estar errado.
- Seleção de idioma por arquivo na interface (Treeview) foi avaliada e descartada: como o idioma real de cada vídeo é lido da própria faixa, o menu global é apenas uma preferência.
